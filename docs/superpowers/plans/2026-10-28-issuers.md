# Issuer landscape and data rooms

The user authorizes a functional Issuers tab and issuer-level market intelligence. Build within the existing Node/vanilla-module app and approved hosting/API budget. The established forest/mint identity, light mode and open, cardless layout remain authoritative. No new dependency or account is needed.

## Direction

Operate mode. A full-width issuer ranking and direct, source-dated metrics make the market legible. Open horizontal share bars provide the visual anchor; no dashboard-card mosaic. Selecting an issuer opens its data room with reported market metrics, mapped asset/network coverage, searchable paginated products, and issuer terms. Real logos identify rows and networks. Fast filter feedback and a single short bar reveal communicate changes; reduced motion disables transitions.

## Evidence and metric boundaries

CoinGecko /rwas/issuers/{id} publishes aggregate token market cap, absolute 24h cap change, volume, token IDs and source time. Reuse the daily issuer observations already collected by bounded discovery. Expose those observations through a narrow server function; do not expose discovery internals or credentials. Source freshness and missing issuers remain explicit. Add a bounded on-demand refresh that shares existing source pacing/cache. Market share is the issuer's reported cap divided by the sum of valid reported caps for the displayed equity-issuer universe; it is not an independently complete global market estimate. Do not sum third-party totals with another source's AUM. Native catalog counts exclude wrappers, which are shown separately. Network counts describe deployments and never allocate aggregate cap to a chain.

CoinGecko aggregates can cover tokens outside Stocklens's verified mappings. Label the two scopes and coverage directly. Do not invent holders, inflows, yields, history or risk scores. Token Terminal and RWA.xyz remain external research links; no new API subscriptions/keys. Existing issuer terms retain their provenance and review limitations.

## Implementation sequence

1. Add tested pure issuer aggregation: identity-based grouping, cross-chain/product deduplication, wrapper handling, numeric/time validation, honest denominator and source states.
2. Add the issuer API and paginated issuer-asset endpoint using catalog identities and existing token-market cache. Validate all query input and bound calls. Serve new modules explicitly.
3. Add the Issuers navigation route and page controller. Preserve Home/Compare/Markets and browser history; issuer selection has a canonical shareable URL.
4. Build open overview/ranking, issuer detail, network presence, sourced terms and product table, search/filter/pagination/CSV, refresh/loading/error/empty states.
5. Test data accounting and HTTP boundaries, then real-source integration plus actual browser desktop/mobile/light/dark and keyboard/navigation checks. Run all tests, production smoke and one design detector. Obtain independent finish/code review, fix material findings, then publish through existing GitHub/Render release flow and verify public access.

## Acceptance

Every existing catalog issuer has a discoverable row, including records without financial observations. Missing values stay missing. Share denominators and snapshot dates are visible. A stock/ETF can be opened from an issuer into the existing Compare flow with that issuer selected. Filtered exports match visible scope. Direct links, Back/Forward, retry, stale data, private storage and phone widths work. No public credentials, fabricated data, extra paid service, or changes to execution/custody.
